# 数据处理与质量

## 先明确数据契约

记录输入来源、版本、格式/工作表、观察单位、时间范围、主键、单位、缺失编码、权重和目标输出。基础输入只读，处理结果写到项目指定位置。精确参数由项目配置决定，不默认城市年面板或平衡面板。

## 处理顺序

1. 检查实际字段、类型、编码、重复与异常。名称标准化只在内存或副本做，保留原字段映射。
2. 明确连接应是一对一、多对一或有意多对多，合并前分别查键。输出未匹配记录和合并后的行数变化，不自动去重掩盖膨胀。
3. 按已说明规则处理缺失、异常、行政变更和时间对齐，区分真实零值与未观测。
4. 对缩尾、插补、对数、价格平减、标准化及综合指数记录范围、参数、样本与单位。不得为了显著性调整转换。
5. 按研究结构校验：面板检查单位—时间键及覆盖；调查检查抽样权重和层级；实验检查分配单位；预测检查训练/验证划分与泄漏。
6. 若研究有处理时间，区分公告、实施、实际上线；只有吸收型处理设定才要求状态不反转。
7. 写出处理脚本、数据字典与质量报告，解释每一步保留和剔除的样本。

详细字段和验收规范见[数据契约](references/data-contract.md)。

## 轻量CSV检查

自带`check_csv.py`读取CSV，输出JSON，不修改数据；适合初检，不处理Excel、不替代研究设计验证。

```text
python <skill-folder>/scripts/check_csv.py <data.csv> --key unit_id --key year --required outcome --numeric outcome --min outcome=0
```

主键、必需字段和阈值必须来自项目，不直接照抄示例。重复键、空主键、指定必需值缺失或数值规则不满足时非零退出。允许缺失的变量不要列为必需字段；报告仍显示各列空值数。缺失编码按需用`--missing`补充。

## 完成标准

样本变化可解释，输出字段和单位匹配下游要求，处理可以重跑。旧样本量只作比较，不为保持原行数强行修值。敏感数据不要在诊断中打印原始记录，优先输出计数与行号。
