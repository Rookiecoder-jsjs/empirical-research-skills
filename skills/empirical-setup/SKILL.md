# 环境搭建与启动

目标：让当前任务使用正确且经过验证的项目环境。先检测再安装，向新手一次解释当前步骤、预期输出和失败后下一步。

## 流程

1. 识别操作系统、终端、项目根目录、既有依赖配置和Python版本要求。能检测的不要让用户重复填写。
2. 读[环境指南](references/environment-guide.md)，只加载当前系统分支。已可用的Python、uv和`.venv`直接复用。
3. 没有项目版本约定时，依据所需包的支持情况选版本并记录；指南中的3.11只是示例，不把任何论文的版本固化。
4. 用户要求搭建后安装所缺部分；只要求查看或解释时不安装。已有环境损坏先保留，不默认清空重建。
5. 创建、激活项目环境，指定该解释器安装依赖。新终端重新激活；独立工具进程直接使用解释器绝对路径，不依赖上次激活。
6. 用自带只读工具检查，再按任务检查专题包和最小计算。命令中的脚本位置从本技能实际安装目录解析，不假定当前工作目录。

```text
<project-python> <skill-folder>/scripts/check_environment.py --project <project-root> --python-version 3.11 --require pandas --require numpy
```

这是参数格式说明，替换为真实路径和该项目所需包再运行。工具仅依赖标准库；未安装Python前先用系统命令查uv，不陷入“用Python安装Python”的循环。

## 环境边界

- `.venv`属于本机项目，不跨系统复制；数据和正文不放入环境目录。
- 研究探索需要额外依赖时，遵循探索隔离约定，不升级正式环境。
- 安装可能写用户级uv/Python/cache目录；说明用途，权限受阻时准确报告，不修改系统安全策略绕过限制。
- 依赖冲突时记录实际错误，不静默删锁定版本、换模型、全部升级或禁用证书校验。
- 现有requirements工作流保持原状；只有项目采用pyproject/锁文件时才用对应同步方案。
- 文档输出和R/Stata依赖按任务准备；基本Python可用不等于所有软件已验证。

## 验收

报告解释器路径、Python/uv版本、环境归属、必需包及冲突检查情况。基础模型检查在合成数据上执行，不运行正式估计。明确区分“基础环境就绪”“专题分析就绪”“文档交付就绪”；检查工具不会安装包或宣称科学结论已复现。
