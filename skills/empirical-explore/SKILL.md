# 隔离探索与采纳

## 探索模式

在项目指定的探索根目录下建立主题工作区。原始输入和正式项目只读，所有脚本副本、数据副本、中间结果、图表、日志、文稿和缓存留在该工作区；不要自动修改正式模型。

记录问题、候选设定理由、对照规格、样本、参数、种子、输入版本和预期输出。保持完整设定清单，不只展示显著的一组。

检查复制脚本的根路径、导入时写文件的副作用、字节码和图形缓存。必要时禁用字节码或把缓存定位到探索目录。需要额外依赖时优先使用隔离环境，不能升级正式项目环境。

专项清洗、分析、写作技能必须继承当前隔离边界。已存在正式结果只读比较，不手工复制修改来伪装为新估计。

## 采纳模式

“采纳一个结果作为补充”“迁移一个脚本”“替换基准模型”是不同范围。根据用户明确要求执行；已有授权不重复询问，但不能扩大到未被采纳的候选。

步骤：明确被采纳对象和用途 → 核验输入与规格 → 保留探索记录 → 必要时迁移脚本/配置 → 脚本重建目标产物 → 核对结果 → 同步受影响正文和运行说明。

项目允许结果留在探索目录并被正文引用时，登记其具体来源和采用范围，不强制搬迁。目录名不能替代证据角色判断。

## 交付

说明尝试了哪些设定、哪些结果有支持、哪些不确定、是否已采纳。采纳记录至少包括用户要求的范围、结果文件、规格、正文用途与仍未获采纳的分支。不根据p值自动给候选排名并选为主结果。
