# 实证研究工作流

目标：把用户当前的一项研究任务做到可核验完成。不要默认新建项目、重跑全部模型或追求某个期刊。

## 开始时

1. 读本项目的AGENTS.md或其他明确约定，识别现有目录、权威输入、研究问题、模型角色和用户要求。
2. 判断需要执行、只读检查、方法讨论还是写作。只读取相关文件，不扫描无关个人目录。
3. 跑程序前检查环境；缺失时使用可用的`empirical-setup`。只改文字不因环境缺失停止。
4. 用户称为“尝试”的任务先限定隔离目录，再调用所需专项；不得由专项默认路径写回正式目录。
5. 明确本次产物、必要上游、可能更新的下游。信息可从文件推断就先核对，只有关键缺失才简短提问。

## 按任务选择

| 当前问题 | 能力 |
|---|---|
| 首次使用、换机器、激活失败 | 环境检查与准备：`empirical-setup` |
| 文件放哪、目录初始化 | 项目组织：`empirical-project` |
| 清洗、合并、构造变量 | 数据处理：`empirical-data` |
| 运行模型、更新图表、复现 | 实证执行：`empirical-analysis` |
| 比较候选、采纳试验结果 | 探索管理：`empirical-explore` |
| 写作、文献、生成交付稿 | 证据写作：`empirical-writing` |
| 追查不一致、检查交付 | 审核：`empirical-audit` |

这些技能属于同一套可选能力，按需读取同级技能。若单独安装而缺少某项，直接执行其职责范围内可完成的工作，或指出缺失工具；不能声称已调用不存在的技能。

## 研究适配

先识别观察单位、时间结构、目标量、可用比较组、识别假设和推断方法。横截面、面板、调查、实验和预测研究采用不同检查；不固定DID、控制变量、样本量、事件窗口或论文结构。

研究角色（基准/稳健性/补充/探索/历史）与技术状态（待运行/失败/待核验/有效/过期）分开。当前结果必须追溯到产物，不从会话记忆复制系数。

## 结束时

说明完成目标、具体产物、验证范围、未完成项及影响。局部修改无需全篇审计；缺少识别支持不能用格式检查替代。不要把本次授权扩展为投稿、发邮件、提交Git、推送或公开数据。
